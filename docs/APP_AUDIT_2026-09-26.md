# Vuneli app audit — 26 Sep 2026

Scope: the whole repo (49 pages, 139 API routes), scored against the repo-quality standard.

## P0 — security (fix before anything else)
1. **~100 API routes have no session check.** Many take `userId` from the query or body and trust it
   (e.g. `dashboard/metrics`, `documents/upload`, `credits/award`, `users/[id]`, `notifications/*`, `lms/*`).
   Anyone can read or change another account's data or award credits.
2. **Dangerous admin/ops routes exposed:** `stripe/reset-customers`, `download-codebase`,
   `marketplace/admin/add-banner-column`, `marketplace/setup`, bulk banner generation, `edit-image`, `gemini/*` (unmetered AI spend).
3. `qa/enter` + `QA_BYPASS_TOKEN` back door must be confirmed off in production.
4. Only 27 of 139 routes validate input with zod.

## P1 — correctness / no invented figures
- `Math.random` in `users`, `documents/upload`, `lms|learn/certificates` routes.
- `compliance/data` falls back to a hard-coded score of 85 when no data exists.
- `compliance/documents/generate` hard-codes 2025 due dates and a US SEC framework (out of Cyprus/EU scope).
- `compliance/route.ts` recommendations are hard-coded strings (incl. "reduces stress by 60%").
- Two parallel course systems (`learn/*` and `lms/*`) and two Gemini SDKs.
- Stubs/placeholders flagged in: studio, settings, onboarding, calculator, learn, grant-alerts, integrations.
